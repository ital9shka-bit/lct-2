# Объекто-ориентированный поиск

**ООП** — платформа поиска талантов через задачи работодателя, наблюдение потенциала и подтверждённые основания. Работодатель описывает потребность, получает подборку и отправляет адресное приглашение. Талант управляет публикацией профиля и доступом к контактам.

Главный акцент демо — **самооценка и применение новых правил**. Профиль объединяет четыре источника: достижения ФСП (FSP), когнитивные наблюдения, самооценку и профессиональную проверку. Отдельная процедура проверяет заявленный опыт. Результат сопровождается объяснением расчёта, источниками и вопросами для дальнейшего разговора.

**[Открыть демостенд](https://lunahub.ru)** · **[Маршрут эксперта](docs/expert-guide.md)** · **[Как устроена оценка](docs/assessment.md)**

Это демонстрация продукта для хакатона. Люди, компании, достижения, подтверждения и предложения в демо вымышленные. Банки ещё требуют независимой экспертизы и пилота; когнитивный блок не выдаёт IQ или валидированный прогноз успешности.

## Запуск из репозитория

Нужны Git, Bash и запущенный Docker с Compose v2.24.4 или новее. Node.js, PostgreSQL и Python на компьютере не требуются. Порты 8088 и 8089 должны быть свободны.

```bash
git clone https://github.com/ital9shka-bit/lct-2.git
cd lct-2
bash scripts/setup.sh
docker compose --env-file implementation/.env -f implementation/compose.yaml up --build --wait
```

Откройте **http://localhost:8088**. `setup.sh` генерирует локальные секреты; существующий `.env` сохраняет. Compose собирает интерфейс, применяет миграции и заполняет демонстрационную базу. Данные хранятся в отдельном томе PostgreSQL и сохраняются после перезапуска. Первый запуск скачивает образы и зависимости.

ИИ и Keycloak для основного маршрута проверки не нужны. Заполненные примеры доступны сразу. Новые открытые технические ответы в режиме `manual` ожидают проверки оператором. Подключение ИИ, SSO и серверный запуск описаны в [инструкции запуска](docs/running.md).

## Проверка сборки

```bash
bash scripts/verify.sh
```

Сценарий создаёт отдельный Compose-проект, образ и свежую БД, выполняет Docker-сборку, миграции, seed, unit- и интеграционные тесты, проверяет HTML, иконки, health и OpenAPI. Затем удаляет только собственные контейнеры и тестовый том. Настройки действующего стенда не используются. Логи остаются в игнорируемой `.qa/`. Нужны свободные порты 19088/19089; их можно изменить через `QA_PORT` / `QA_MAIL_PORT`.

Последний локальный прогон: **32 unit-теста и 39 интеграционных тестов**, 11 октября 2026 года. [Область проверок](docs/testing.md). Подготовлен [шаблон GitHub Actions](ci/verify.yml); [инструкция включения CI](docs/testing.md#github-actions).
