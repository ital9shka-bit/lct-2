# API

Основной префикс — `/api/v1`, формат — JSON. Действующий машинный контракт доступен без входа:

- Локально: http://localhost:8088/api/v1/openapi
- На демостенде: [lunahub.ru/api/v1/openapi](https://lunahub.ru/api/v1/openapi)
- Базовый контракт в исходниках: [`implementation/private/openapi.json`](../implementation/private/openapi.json)

Сервер объединяет базовый контракт с расширениями в `src/extensions.mjs` и `src/experience-contract.mjs`. Runtime endpoint содержит итоговую версию: в проверенной поставке **82 пути и 94 операции**. Файл `deliverables/v08/05_api.openapi.json` — исходный контракт ТЗ; он не описывает все добавленные функции текущего демо.

## Группы операций

| Область | Примеры путей | Доступ |
| --- | --- | --- |
| Вход | `/auth/otp`, `/auth/otp/verify`, `/auth/oidc/*` | До сессии; Origin и проверки маршрута |
| Профиль и программа | `/me/resume`, `/me/self-assessment`, `/me/program`, `/me/summary` | Талант, собственные данные |
| Техническая проверка | `/assessments/attempts` и задачи/действия/результаты попытки | Владелец попытки; операторские операции отдельно |
| Когнитивный блок | `/cognitive/sessions` и задачи/обратная связь/действия | Владелец сессии |
| Компания и потребности | `/me/company`, `/needs` | Работодатель своей компании |
| Подбор и профили | Операции matching, шорт-листа и профиля в контракте | Работодатель; серверная проекция и разрешение контактов |
| Предложения | `/invitations` и действия над приглашениями | Своя компания или адресат |
| Вакансии и отклики | `/vacancies`, `/applications` и их действия | Согласно роли и принадлежности |
| Опыт | Заявления, review и решения в расширении опыта | Талант / оператор, согласно операции |

Точные методы, URL, поля и ответы берите из runtime OpenAPI. HTML-интерфейс использует этот же API; скрытая кнопка не заменяет серверную проверку прав.

## Общие правила

- HttpOnly cookie `oop_session`; CSRF token приходит после входа и передаётся в `X-CSRF-Token` при изменениях.
- Изменяющий запрос требует корректный Origin; для предусмотренных операций — `Idempotency-Key`.
- CAS-поля `expected_revision` / `draft_revision` предотвращают перезапись устаревших данных. При 409 загрузите текущее состояние.
- Неизвестные поля отклоняются; схемы проверяются AJV. Владельца и компанию сервер определяет по сессии.
- Ошибка содержит `code`, `message` и предусмотренные контрактом поля; ключи и stack trace не возвращаются.
- 401 — нет сессии; 403 — нет права/неверный CSRF; 404 — нет доступного объекта; 409 — конфликт; 410 — истечение; 422 — поля; 429 — лимит; 503 — недоступная зависимость.

`GET /health` проверяет API и подключение к PostgreSQL. `GET /api/v1/meta` сообщает режим демо, авторизации, ИИ и статус банка. Он не сообщает секреты. Runtime контракт и ключи банка различаются: правильные ответы, эталоны и приватная рубрика не выдаются как публичный банк.

Интеграционные тесты показывают полноценные запросы с cookie, Origin, CSRF, revision и idempotency, включая отрицательные сценарии. Их запуск описан в [проверках](testing.md).
