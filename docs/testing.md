# Сборка и проверка

Для проверки экспертом:

```bash
bash scripts/verify.sh
```

Сценарий воспроизводит запуск с пустой БД и новым environment. Создаёт собственные Compose project/image/volume, мигрирует и заполняет их, проверяет API и удаляет только свои контейнеры/том. Существующий `implementation/.env` не используется. Все ИИ-параметры пусты; внешние платные запросы не выполняются.

Порты: 19088 и 19089. Пример изменения: `QA_PORT=19188 QA_MAIL_PORT=19189 bash scripts/verify.sh`. Результаты находятся в `.qa/<project>/unit.log` и `integration.log`; при ошибке сохраняются `services.log`. Environment с секретами удаляется, каталоги логов исключены из Git и Docker context.

## Что проверяется автоматически

Unit-проверки: точные технические пороги и минимумы компетенций; ветвление A/V; цитаты и критерии; интервалы активного времени; структура и достижимость банков; подбор и дубли ФСП; состояния когнитивных пар; grounded-извлечение резюме; протокол ИИ; OIDC/JWT.

Интеграционные: cookie/CSRF/роли и объектные права; CAS-гонки и идемпотентность; сохранение и явное завершение самооценки; пауза и возобновление; замороженные вопросы; очередь оценки и ручной результат; доступ к контактам и его отзыв, в том числе PDF; вакансии, отклики, фильтры/шорт-лист; версии опыта и решения; заполненность готового демо; когнитивная обратная связь и одинаковые основания в проекциях; demo/обычные лимиты OTP и параллельные входы; ошибки OIDC и блокировка операторского OTP.

Интеграционные тесты создают синтетические записи и меняют состояние БД. Их нельзя запускать на действующем публичном стенде или базе с данными зрителей.

## Разработка

При локальном Node.js ≥20 можно выполнить unit-проверки:

```bash
cd implementation
npm ci
npm test
npm run build
```

Runtime требует DATABASE_URL и environment из шаблона. Полный маршрут проще воспроизводить `scripts/verify.sh`: он включает Poppler, шрифты и PostgreSQL в тех же контейнерах, что обычный запуск.

Технические банки формируются при сборке через `tools/build-extended-banks.mjs`. Серверные исходники и клиентский JavaScript проходят `node --check`. Не редактируйте `public/`: он пересобирается из `prototype-v13` и `client/`.

## Что проверять вручную

Следуйте [маршруту эксперта](expert-guide.md) на широком и мобильном экране. Посмотрите главный вход, видимость согласия, краткие модальные пояснения тестирования, чтение вопроса, результат и его основания, страницу работодателя и формы предложения. Автотест API не доказывает качество вёрстки каждого размера экрана.

Реальный провайдер ИИ, SMTP вне Mailpit, DNS/TLS серверного домена и независимая экспертиза вопросов требуют своего окружения и не входят в воспроизводимый офлайн по ключам тестовый маршрут. Реальный Keycloak запускается отдельным Compose overlay; unit/integration проверяют протокол с контролируемыми данными. Инструкции: [запуск](running.md), [методика и границы валидации](assessment.md).
