# Полный банк профессиональных заданий ООП

Версия backend 0.8.0. Backend Junior и Middle. 60 семейств, 120 полностью сформированных вариантов. На попытку выдаются 20 вопросов, из них 10 закрытых и 10 открытых. Ключи, эталоны и рубрики — внутренние материалы разработки, их нельзя включать в клиентскую сборку.

Статус: авторская версия сформирована. Перед выдачей реальных подтверждённых категорий каждое задание и эквивалентность вариантов проверяют два независимых специалиста. Пороговые значения версии 0.8 фиксированы для реализации, эмпирическая валидация описана в ТЗ. Это не заявление о проведённой валидации.

Каждый открытый ответ оценивается по четырём перечисленным бинарным критериям, 1 балл за каждый. Термины без обоснования по условию не засчитываются. Эквивалентное корректное решение допустимо. Противоречие обнуляет затронутый критерий. Если доказательство нельзя уверенно сопоставить критерию — review.

## План выдачи

B: по два вопроса каждой компетенции. A и V: по одному каждой компетенции. Для A выбирается repair при B по компетенции <75, иначе transfer. Для V repair при предварительном C по компетенции <70 либо A<2, иначе transfer. Предварительное C=(0.7B+0.15A)/0.85; B и A здесь в процентах. Выбор фиксируется по полным пяти A. B вариант 1/2 выбирается серверным HMAC; в A/V LLM выбирает один из двух approved вариантов назначенного семейства по предыдущим ответам. При ошибке весь этап выбирается резервным HMAC. Выбранные id сохраняются и не меняются при refresh; client seed не принимается.

Внутри стадий порядок HTTP, SQL, Debug, Architecture, Security; B содержит два слота подряд. Форматы: B 6 закрытых/4 открытых; A 2/3; V 2/3. Семейства repair и transfer относятся к одному целевому грейду.

### Middle-V-security-1-transfer-2

Компания удалена из членства пользователя, но его старый session token содержит company_id. Как защитить приглашения и контакты?
